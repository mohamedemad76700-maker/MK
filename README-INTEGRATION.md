# MK School V50 — تشغيل بدون Docker

## المتطلبات
- Node.js 22 أو أحدث
- PostgreSQL وRedis مثبتان ويعملان محليًا؛ Redis مطلوب لمحددات الطلبات وحماية واجهات الخادم
- FFmpeg إذا كان رفع الفيديو وتحويله مطلوبًا

## ملاحظات التخزين
- لا يستخدم المشروع `localStorage` أو `sessionStorage` أو IndexedDB لتخزين بيانات المدرسة. الجلسة والبيانات المؤقتة في ذاكرة الصفحة فقط؛ بعد تحديث المتصفح ستحتاج إلى تسجيل الدخول مجددًا.
- قاعدة PostgreSQL هي مصدر بيانات المنصة. ترحيل `0012_record_level_platform_state.sql` ينقل الحالة القديمة إلى مجموعات وسجلات منفصلة مع مراجعة التعارض بالـrevision؛ لا تعود بيانات المدرسة مخزنة كحمولة JSONB ضخمة واحدة.
- تُرفع الملفات إلى مجلد خادم `MEDIA_ROOT/school-files` وتُسجّل بياناتها وبصماتها في جدول `school_files`. لا تُرسل المرفقات كـdata URLs داخل حالة المدرسة. روابط الملف الموقعة قصيرة العمر، ويُتحقق من الجلسة والصلاحية عند فتح المحتوى.
- أي مرفق كان موجودًا حصريًا في تخزين متصفح قديم لا يمكن للنظام الجديد استيراده تلقائيًا؛ أعد رفع هذه المرفقات بعد تسجيل الدخول. بيانات الخادم الموجودة في PostgreSQL لا تتأثر بذلك.

## تشغيل
1. انسخ ملف `.env.example` الموجود في مجلد المشروع الرئيسي إلى `.env`، أو نفّذ `node video_engine_backend/scripts/init-env.cjs` لإنشاء إعداد أولي.
2. اضبط `DATABASE_URL` و`REDIS_URL` و`JWT_SECRET` قويًا، مع بريد المدير وكلمة مرور bootstrap فريدة. لا تشغّل الخادم مع قيم `CHANGE_ME`.
3. ثبّت الاعتماديات بـ `npm install` داخل `video_engine_backend`.
4. شغّل `start-all.bat` على Windows أو `bash start.sh` على Linux/macOS. عند إنشاء `.env` للمرة الأولى، اضبط الخدمات ثم أعد تشغيل المشغّل.
5. اختبر `/health` ثم سجّل الدخول وجرب رفع ملف وربط ولي الأمر ودورة مدرسية في بيئة اختبار.

## الحد الحالي
تجهيز البيانات كسجلات مستقلة يقلل التداخل الناتج عن استبدال سجل JSONB واحد، لكنه لا يغني عن اختبار ضغط ومراجعة تشغيل فعلية قبل اعتماد آلاف المستخدمين. لم يُختبر المشروع هنا أمام قاعدة بيانات حقيقية أو حمل إنتاجي، لذلك لا يُعدّ هذا التقرير شهادة جاهزية للإنتاج واسع النطاق.
